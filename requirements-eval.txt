# Evaluation only. Separate from requirements-rag.txt because RAGAS drags in
# roughly forty packages - datasets, pandas, pyarrow, scipy, scikit-network,
# instructor, and OpenAI's client - none of which belong in the service that
# answers questions. Scoring is an offline job; the service should not carry
# the scorer.

-r requirements-rag.txt

ragas==0.4.3

# - Not optional, and not a preference. RAGAS 0.4.3 declares langchain-community
#   without an upper bound and imports
#   `langchain_community.chat_models.vertexai`, which 0.4.x removed. Installed
#   against the current release it resolves cleanly, installs cleanly, and then
#   raises ModuleNotFoundError on `import ragas`. 0.3.31 is the last release
#   that still carries that module, and it coexists with langchain-core 1.x.
#
#   Remove this pin only after checking that `import ragas` still works.
langchain-community==0.3.31

# - Not brought in by ragas's own `instructor` dependency: that installs
#   instructor's base package, not its `google-genai` extra. The Gemini judge
#   (evaluation.py's build_judge, on the default RAG_PROVIDER) needs it -
#   instructor.from_genai()'s structured-output path raises
#   "ConfigurationError: The 'jsonref' package is required for Gemini
#   structured output" without it. Found live, not from a changelog: a real
#   Faithfulness.score() call against Gemini failed on this before it was
#   added.
jsonref==1.1.0

# - evaluation.py's build_judge imports instructor, google.genai and openai
#   directly now (patching a raw async client per provider, since ragas's own
#   collections metrics and llm_factory both turned out not to work for this
#   - see task-4-report.md). All three previously arrived only as transitive
#   dependencies - instructor via ragas (whose own pin on it has no version
#   bound at all), google-genai via langchain-google-genai, openai via
#   langchain-openai - so nothing here pinned the exact API build_judge
#   depends on. instructor in particular is mid-migration between a v1 and v2
#   tree; an unpinned bump could silently change or remove the
#   from_genai(..., use_async=True) / Mode.JSON surface this relies on.

#   run against.
instructor==1.15.4
google-genai==2.17.0
openai==2.54.0
